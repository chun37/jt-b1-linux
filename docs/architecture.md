# 構成と検証範囲

## 元構成から取り出したコード

GUIは2026年11月6日の音量保持版を基点にしています。
音声監視は同日のAUX対応版、通信と表示はそれぞれの常用ソースから選別しました。
公開版は個体固有設定を除き、PCでの利用とテストのために整理したものです。
実機から稼働中の認証状態を吸い上げたり、元の成果物ディレクトリーを丸ごとコピーしたりしていません。

```text
GUI supervisor
  ├─ physical buttons / boot playback
  ├─ Spotify Web API (metadata + refresh)
  ├─ Soloist local API → PulseAudio → private ALSA → stock audio driver
  └─ application frame → system shell → fb0
                           └─ clock / route / battery / NAS status

Wi-Fi supervisor → stock wl12xx + process-local nl80211 shim
povo supervisor → AT session + GobiNet WDS → usb0
```

`system_shell.py`がフレームバッファーを描き、上44pxに共通バー、下600×980にアプリ領域を作ります。
論理600×1024を物理1024×600へ回転し、タッチ入力は逆変換します。
アプリの異常終了と未完了の操作子はGUI監督が回収します。
全プロセスの強制終了やハードウェア障害を保証する設計ではありません。

## PCで検証するもの

| 分類 | テストする内容 |
| --- | --- |
| 認証とAPI | PKCE、Hostとstate、期限、保存権限、refresh、APIパス、HTTPエラーの非秘密化 |
| GUIと入力 | 回転と逆変換、タッチrelease、領域境界、タイル、描画、物理キー、操作子回収 |
| 起動と音声 | boot単位の一回要求、曲と音量の保存、共有ロック、出力監視の状態確認 |
| 携帯 | 合成TLV、IPv4、APN制約、DNS追記と清掃、再接続、シリアル競合の模擬復元 |
| 補助ツール | LED方針と実値ドリフト、辞書の非評価、ステージング、設定、プレビュー、Cの座標と描画 |

PCテストは実機ドライバーをロードしません。
IPは文書用の合成アドレス、OAuth値はテスト用の文字列、ロゴ画像は合成fixtureです。
フォントは利用者の環境にインストールされたNoto CJKを使います。

## 公開時に変えた点

Client IDを環境変数または端末設定から読むようにし、未設定時のWeb API要求を拒否しました。
携帯限定HTTPS検査はimport時に実行せず、明示的なネットワーク試験フラグと新鮮な接続状態を要求するようにしました。
シリアル所有プロセスの自動停止を初期値で禁止し、ATポートをMC7700のUSB IDとinterfaceで絞りました。
辞書変換は入力と出力を引数にし、既存ファイルを上書きしません。
元のデプロイコードではなく、新しいPC専用ステージングとプレビューを付けています。

これらの変更を含む公開版は実機へ再配置していません。
元構成の実機確認と公開版のPC検証は区別します。

## 元構成で残った制限

独立復旧と全体像の実機復元は未検証です。
サスペンド、長時間運転、電池計測の精度、基地局移動、実Wi-Fi切断時のアプリ切替も評価が残っています。
Soloistの受信コーデックとビット深度の独立監査はしていません。
AUX機器への実接続と公開版の全経路の発音も未確認です。
